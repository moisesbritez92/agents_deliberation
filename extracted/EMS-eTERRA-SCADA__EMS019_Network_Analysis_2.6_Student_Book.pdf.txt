PWRFLOW   features
Supports  a  wide  variety  of  problem  definitions   including diverse  voltage  
levels  and  multiple  islands
Provides  load  scheduling  capability  through  load  profiles and  load  
distribution  coefficients
Models  regulations :
− Voltage regulations  (AVR)  by  generators,  transformers,  circuit  
breaker operation  (capacitor/reactor  connection  status)
− MW  flows  regulations  by  AWR  phase  shifting  transformers
− AGC model for  area  interchange control   and  load + loss  coverage
Provides  both  standard  and  expert  operator  interfaces
Uses  the  full Jacobian Newton-Raphson  solution method  to calculate  
voltages  at  all  buses

Automatic   network  functions  :  MW regulation
Automatic Watt  flow Regulation  (AWR)    
− Adjusts the phase shifter taps to regulate  the MW flow  through the phase 
shifters
− Regulation is abandoned when regulating variable reaches limit
Area  interchange control  and load + loss coverage   
− Area interchange :
Sum of tie MW flows   =  scheduled net interchange
− Area balance equation : 
GENERATION  + IMPORT   =   LOAD + LOSSES + EXPORT
− Adjusts MW generations through model of area AGC :
• Single slack bus  Î multiple slack generators
• base generation  +  participation factors
− Area in which MW balance cannot be established is DEAD
− Interchange is not regulated in areas split by islanding 
− One angular reference per island

Summary of  MW   load  model characteristics
Time dependence   only at   LDAREA level
− Thus, load profiles can only be defined at this level
− Avoid too many hierarchical levels (multiplying profiles)
Magnitude of base portions  are not proportional to the parent area 
load 
Base  portion of loads can corrupt the load distribution mechanism if 
not consistent upwards
− Group all bases of similar behavior together in a loadarea with the 
desired profile  (schedule)
Base portions of loads are not updated by RTNET

RAS / RAP Overview
What are RAS/RAP?
− These are a set of protection schemes to implement in order to 
prevent overloads or loss of equipment.
− These schemes are either:
• RAS (Remedial Action Schemes): Automatic actions taken in the field
• RAP (Remedial Action Plans): Preventative actions executed manually
Why simulate these Schemes in Network Applications?
− Allows the user to verify the effectiveness of RAS/RAP schemes 
using a study power flow
− More accurate results from Contingency Analysis, VSAT, and TSAT 
when they model RAS/RAP
− DTS Events can benefit by importing these schemes
− Market impacts (SFT & identifying valid constraints)

Weighted Least Squares  (WLS )
The best estimate of the state variables X is obtained by the Weighted 
Least Squares (WLS)  method. The objective is to minimize the sum of the 
squares of the weighted deviations of the estimated measurements from 
the actual measurements: 
Min  J(X)   =   Sumj { [ yj -h j(X) ] / σj }2
σ reflects the measurement uncertainty
The value  of J  is  called the “cost”of the solution.
In matrix notation, 
J(X)  =  [y-h(X)]T W-1 [y-h(X)]
W is the covariance matrix of measurement errors, which reflects
the measurement confidence. In the case of independent 
measurement errors,  W-1   is diagonal with
wjj = 1/σj

Weighted Least Squares  (WLS )
J(X)  =  [y-h(X)]T W-1 [y-h(X)]
Minimization of the cost is achieved by solving:   
∂J(X) / ∂X  =  0
Since J(X) is non-linear, the solution is obtained iteratively.
The method uses the Taylor’s series expansion for the function h:
h(Xk+1)   =    h(Xk)  +  H(Xk) ΔX
with H : Jacobian matrix of partial derivatives of  h  wrt  X, 
Xk : estimate of X at iteration k, 
At each iteration k:
[ HT W-1 H ] ΔXk = HT W-1 [Y- h(Xk)]
ΔX=X k+1 -X k =   [ HT W-1 H ]-1 HT W-1 [ Y - h(Xk) ]

RTNET  :   Network   observability
The network observability function  determines which state variables, and 
which measurements (and the associated equations)  will constitute the 
state estimation problem formulation.
The availability of usable measurement from SCADA  and model injection 
information determines which equations can be used.
The determination of the extent of “measurement observability” itself is 
based directly on two basic rules which are repetitively applied:
− A branch flow is “known” if the buses at each end are in the same 
observability island.
− If all “unknown” branches incident to a measured injection bus 
terminate in observability island X, then the injection bus is also in 
observability island X.
− In addition, there must be a least one known voltage magnitude in 
an observability island in order for it to be observable.

Error detection
Error detection
− Based on CHI-square  test:
• the  solution cost “J” follows a CHI-square distribution with M-N 
degrees of freedom 
( M-N = number of measurements – number of state variables).
• J will be larger than expected in the presence of bad measurement 
data 
Error identification
− Based on equation residuals evaluated at the calculated network state:
• Residual = estimated value  - measured value
• Large residuals  generally indicate that  the associated measurement 
(or bus equation)  is grossly in error or anomalous

Error processing
− Analyze individual equation residual whose value is larger than 
expected and propose weight adjustment to reduce the influence of 
those measurements upon the solution
− Perform sensitivity analysis  of equation residuals  to the proposed 
weight adjustments
− Select and implement  weight changes
− Re-solve WLS  to obtain new state solution
− Check total cost  and  equation residuals again:
• If acceptable, solution is valid
• If not, repeat error processing and weight change steps

Task 3: View State Estimator Residuals and Mismatches 
Reminder  and terminology clarification : 
• Mismatch = violation of the firs t Kirchhoff  law when calculating the 
network flows from the considered voltage vector = balance of the 
power flows at a bus. This balance is zero for an exact network 
solution (satisfying exactly the 2 Kirchhoff laws). Any network 
solution in which the maximum mismatch is less than a user-
specified tolerance is considered valid. The mismatch is a power 
flow concept. 
 Proprietary – See Copyright Page 3-63 
 RTNET Solution Quality Evaluation Error Analysis 
Network Analysis 
• Residual = difference between a measured value and the 
corresponding estimated value. The residual is a state estimation 
concept. 
• In principle,  the state estima tor does not know the concept of 
mismatch. Indeed  :  
- The primary result of the st ate estimator algorithm is the 
estimate of the   voltage vector. 
- This voltage estimate is used to calculate the estimate of  line 
flows.  
- These  line flow estimates allo w to calculate the net injection 
estimate at each bus as the balance of line flows. 
- The difference between the net injection estimate and the 
measured net injection is distributed over the injection 
components (generation and load)  in proportion of their 
variances  by pushing them further away from each other  or 
closer to each other until obtaining a net injection equal to the 
estimated net injection (note that in this process, the model 
value is used in absence of measured value) 
- With this procedure, the state  estimator solution never shows  
any bus mismatch. 
- There are however 2 exceptions : 
 In case this procedure yields a generation estimate outside 
the generation limits, the estimated generation is moved to 
the violated limit 
 In case this procedure yields  a load estimate outside the 
load limits, the estimated load is moved to the violated limit 
- Both corrections will generate a mismatch that will be listed to 
draw the user attention on the problem.

Task 6: Tap Estimation 
In this part of the lab you will run  RTNET  to perform transformer tap 
estimation. You will first disable a tap measurement from being  used by 
the state  estimator. You will then change the tap position in the simulator, 
and ask the state  estimator to estimate the new tap position. 
1. Bring up the  Network Online Sequence   display in one viewport. 
2. Find a transformer that can be tap estimated and with tap 
measurements.  For being able to be tap estimated, a transformer 
should have its 2 terminals in the same observability island and 
redundant flow measurements, or voltage measurements  on  both the 
high and low sides of the transformer.  Use for instance   transformer 
T1 at the CEYLON  substation which meets these conditions. 
3. Call up the   Telemetered Network Da ta    display at CEYLON.   Note 
that the SCADA  tap  and the  estimated  tap are the same (i.e. tap Xo

Error Processing and Identification Logic (2)
Processing Steps and Process Parameters
1. Solve WLS problem.           
2. Calculate quadratic cost = the sum of the squared and weighted 
residuals. 
3. Calculate Probability Confidence, shown on record display if the “Enable 
Error Processing” option is set. 
Select the “Enable Error Processing” option
4. If Probability Confidence < CONFDES, then the Solution is Valid. 
“Error-Detection Confidence” (CONFDES), typical value 0.90 P.U. 
5. Determine Suspect Equations.  If Weighted Residual > Breakpoint,
equation is Suspect.

Summary of Network Analysis (1 of 3)
The network analysis applications are used to simulate the electric 
power grid for given times and conditions.
Network Analysis can be performed in the real-time or study 
environment.
The output from these applications provides:
− an assessment of the current network state, including:
• Flows and Voltages
• Device Outages
• Split Buses
• Islanding
− an indication of overloads
− an indication of high/low voltage
− the likely effect of pre-defined contingencies on the given network

Summary of Network Analysis (2 of 3)
The network database, NETMOM, contains all of the information 
necessary for the applications to calculate a power flow as best
they can and to report anomalies to the user.  
Included in the database is the definition data as well as all output 
data from the system analysis:
− Topology – how each device is connected into the system
− Device Parameters – impedances, MW/MVAr limits, tap data, etc.
− Limits – Operating limits for branches, interfaces, node voltage
− Schedules – CB Status, Voltage Regulation, Load Area
− Monitoring Criteria – what is an overload and when should it be 
reported
− All output data – Bus Voltages, MW/MVAR flows, loads, 
generation, tap positions, violations, etc.

Summary of Network Analysis (3 of 3)
The contingency database, CTGS, contains all of the information 
necessary to define a contingent network for use during analysis.
The CTGS database also contains all of the processing parameters
for the contingency analysis software.
Included in the database are:
− The contingency definitions – component outages, processing type, 
activation, processing flags, etc.
− Conditional Components – a monitored element and its associated 
component outages
− Processing Tolerances and Parameters – values specifying solution 
tolerances and processing parameters.  These are used in 
determining how many contingencies are processed during full 
processing and what should be reported as a violation.

Summary of Real-Time Network Analysis
(1 of 3) 
The most commonly executed Real-Time Network Analysis Tasks 
include:
− RTNET:  A State Estimator which calculates the real-time network 
state for the given set of input (both real-time SCADA and model 
data). 
− RTCA:  Real-Time Contingency Analysis calculates the contingent 
network state for selected contingencies using real-time data from 
RTNET.
Online Network Sequence (OLNETSEQ) coordinates the execution 
of the real-time network analysis tasks.
In the real-time environment, there is only one instance of each 
application (clone), which means that all users are viewing the 
same set of data.

Summary of Real-Time Network Analysis
(2 of 3)
RTNET simulates the current state of the system using 
− Real-time data from SCADA
− Model data 
RTNET uses pseudo- measurements to fill in areas where SCADA 
data is not available in order to increase observability.
The RTNET solution satisfies, as best it can, Kirchoff’s Law – the 
sum of the flows at each bus must be zero.
To determine the quality of SCADA measurements, i.e. bad data detection, 
you must have redundant measurements.

Summary of Real-Time Network Analysis
(3 of 3)
The RTNET solution matches, as best it can, the SCADA values for
all flows and voltages.
RTNET processing uses only ‘good’ data from SCADA and is able to 
identify anomalous or “bad” measurement data.
A valid RTNET solution can be used as a basecase by downstream 
applications.
To determine the quality of SCADA measurements, i.e. bad data detection, 
you must have redundant measurements.

Summary of Study Network Analysis
(1 of 2) 
The most commonly executed Study Network Analysis Tasks 
include:
− PWRFOW:  Study Power Flow simulation calculates the network 
state for a specific time and set of conditions as defined by  the 
user.
− STCA:  Study Contingency Analysis calculates the contingent 
network state for selected contingencies for a specific time and set 
of conditions as defined by the user.
The Study Network Analysis application (STNET) can include any or 
all of the study tasks and is used to coordinate their execution.
In the study environment, there can be multiple instances (clones) 
of the same application (i.e.:  STNET), so each user can work 
independently without impacting anyone else.

Summary of Study Network Analysis 
(2 of 2)
PWRFLOW simulates the state of the system for a specific time and 
set of conditions as defined by the user. 
PWRFLOW’s solution depends on the basecase from which it was 
initialized and model data.
A basecase can be retrieved from:
− RTNET (real-time data initialization).
− a savecase (savecase directory).
− another user’s study (network copy)
PWRFLOW is typically used to study:
− Outages (Planned and Unplanned)
− Peak and Low Load Periods
− Change in Transactions

Summary of Contingency Analysis 
(1 of 2)
Contingency Analysis can be executed within the real-time and 
study environments:
− RTCA:  Real-Time Contingency Analysis is executed in sequence 
with RTNET by OLNETSEQ.
− STCA:  Study Contingency Analysis is executed in sequence with 
PWRFLOW by STNET.
Contingency Analysis assesses the impact of user defined 
contingencies upon the basecase network.
The basecase for RTCA is copied automatically from RTNET during 
the real-time sequence.
The basecase for STCA is contained within STNET.  Once STNET 
has been initialized, no further initialization is needed for STCA. 
You design and define contingencies for CA.

Summary of Contingency Analysis 
(2 of 2)
Contingency Analysis processing consists of several steps:
− DPF – A decoupled powerflow is run on the initial basecase
− Screening – A quick analysis is run on all active contingencies 
looking for potential violations
− Selection – The screening results are ranked and the worst are 
selected for full processing.
− Full Processing – A complete powerflow analysis is done on each 
of the selected contingencies.
Contingency Analysis reports violations based on the defined 
monitoring criteria.  Violations include:
− Branch overloads
− High/Low voltage
− Interface Flow
− Phase Angle Difference  
− Loss of Load/Loss of Generation

Network Analysis | Conclusion | P13
Conclusion
The network analysis applications provide the tools necessary for 
operators to evaluate the current state of the system.
The network analysis applications also allow the user to study 
various scenarios like upcoming outages or peak load periods.
These tools can be used to assist in the planning of outages as well 
as scheduling generation and/or interchange.
The network analysis applications can alert the user of current or 
potential overloads.
The applications can also be used to track down problems with 
SCADA data.

Network Analysis Terms
Basecase:  Any valid and solved model of the power system.
Mismatch:  The difference between the amount of flow into a bus and the 
amount of flow out of a bus.
Contingent Network:  Networks resulting from user-specified component outages 
and switching operations 
Cost:  A metric for the fit or level of consistency between the measured or 
modeled value and the estimated value.
Degree of Freedom:  The difference between the number of equations and the 
number of variables. 
Factor:  Type of RTNET iteration.  A factor iteration does a complete rebuild of 
the Jacobian matrix.
Flatstart:  Processing initialization.  It sets all bus voltages that are not regulated 
to 1.0 pu and 0 degrees.  Those that are regulated will be set to their 
scheduled target regulation value.

Network Analysis | Appendix A | P6
Network Analysis Terms
Full Processing:  Part of contingency analysis, full processing runs a full 
powerflow solution on the selected contingencies.
Measurement-Observable: Portions of the network where RTNET can estimate 
the state using measured data.
Observable:  Portions of the network where RTNET estimates the state using 
available measurements, but primarily modeled data.
Preferred Tap:  A tap that is estimated by RTNET based on voltage and flow 
measurements.
Pseudo-measurement:  Value generated from model data or ICCP data to fill in 
gaps where measurement (SCADA) data is not available.
Refactor:  Type of RTNET iteration.  A refactor will update the matrix with any 
changes that have occurred since the last iteration.

Network Analysis | Appendix A | P7
Network Analysis Terms
Repeat:  Type of RTNET iteration.  A repeat iteration uses the matrix as it was in 
the last iteration.
Savecase:  A database or set of databases saved for future study.
Screening:  Part of contingency analysis processing, screening does a quick 
evaluation of the contingent network, looking for potential violations.
Selection:  Part of the contingency analysis processing, selection occurs after 
screening.  It ranks the contingencies found by screening and sends the 
highest ranked contingencies to full processing.  The number of contingencies 
sent to full processing by the selection process is based on the contingency 
selection parameters.
