and the economics of  the power system:
− For  the basecase  network state (current  or  postulated) 
− For  contingent  network states.

limits
An optimal state is a feasible state for which the operating cost  has been reduced to

Lab: Enhancing Network Security 
Using STSENH 
In this lab, you will use the STSENH application to evaluate/ improve  a 
network state before contingencies (basecase) and after contingencies. 
 
Objectives 
Upon completion of this lab, you will be able to : 
• Initialize STSENH with data 
• Run a network security enhancement   study and  view the results 
• Use  Security Enhancement  to determine control actions to relieve 
violations in the basecase and in contingency cases 
• Modify the SENH optimiz ation problem definition 
• Create a savecase of the STSENH results. 
Except when otherwise stated, all the displays used in this lab belong to 
the STSENH application.

You  have to retrieve savecases of the following databases : NETAPP, 
SENHAPP, NETMOM, CTLMOM, CTGS, DPF.

default application characteristics.

contains all the other databases.  
• Retrieve the  ENTIRE  savecase  titled   TRAIN_NET_FEATURES.   
Note: You can also navigate to the savecase list via the Menu Bar : 
HABITAT Applications /  Savecase Manager / Savecase Manager master 
and there, select the desired application.

Task 6: Restrict one Control Variable 
In this part of the lab, you will reduce the move magnitude available to one 
of the control variables. The result should be a more  expensive solution. 
1. Find a generator that was significantly moved by the cost minimization 
run, for instance the generator at WVILLE. 
Note the initial generation: …….….……….. MW  
and the generation recommendation: ………………… MW 
2. Call up the  View Controls  tab  of the   Define Controls  display.  
3. You will reduce the magnitude of t he allowable move in the direction 
the MW generation was initially moved (make the limit  enterable and 
modify the adequate  limit, so as to prevent the unit to move  as far as 
it moved in the previous run).  
For instance, change  the max generation at WVILLE from 1000 to 400 MW. 
(Do not change a limit to a value that would make the current 
generation unfeasible. In this case, SENH would not attempt to move 
that control anymore).

Lab 2: Optimal Power Flow Background 
This section contains a short text that summarizes the basic concepts 
involved in optimization problems, and how these concepts apply to the 
optimal power flow problem.  This text will also drive you to some of the 
OPF displays to show where  the concepts apply.  
Students who are not familiar with optimization problems will benefit from 
reading this text before proceeding to the subsequent lab.   
Students who are already familiar with these concepts can jump directly to 
the next lab (using OPF). 
1.1 Optimization Problems 
Any optimization problem is defined in terms of : 
• An objective function to optimize (usually a cost to minimize). 
• Control variables that are allowed to be moved by OPF to correct 
constraint violations and/or improve the objective function. 
• Constraints that put high and low limits on the feasible range for 
state variables and control variables - these are known as 
inequality constraints. OPF also enforces equality constraints, 
which impose relationships (such as Kirchoff’s laws) between the 
variables.  
The Engineer/Analyst sets up these various elements of the problem in 
the OPF databases.  The procedure to setup these problem elements will 
be the object of a subsequent module.  In the present module the user 
only activates or deactivates these elements to modify the problem 
definition.

1.2.3 OPF Constraints 
1.2.3.1 Equality Constraints and Regulations 
In the OPF problem, the equality constraints are the power flow equations, 
including area MW interchange constraints (if applicable).  
The powerflow equations can also include more complex relations to 
represent regulations that can exist in the power system. For instance, 
voltage regulation can exist at various places by various network 
components (generating units, transformers, shunt reactances). These 
constraints model the physical or operational characteristics of the power 
system behavior. 
For controls that are activated to participate in optimization, the local 
regulation is disabled, because the goal is to determine the optimal target 
for regulation. Thus, their existing regulation target is ignored by OPF in 
order to determine the optimal regulation target. 
For controls not activated to participate in optimization, local regulation (if 
defined) will be maintained during the optimization. This applies to devices 
that are physically located in the external model, or that are not needed or 
not available for optimization.   
OPF will impose the local regulation target if: 
• the regulating device is not  activated as a control  
 Proprietary – See Copyright Page 2-24 
 Basic Features of OPF and VVD 
Network Optimization 
• and the regulating variable  is sp ecified as ON-regulation (ON-AVR 
or ON-AWR) in the corresponding network component summary 
display,  
• and if the global regulation flag is enabled 
Your task : See these global regulation mode flags on the OPF Options  
display. Do not modify any data.  
1.2.3.2 Inequality Constraints 
Inequality constraints represent high and low operating limits on the power 
system elements. 
1.2.3.2.1 Monitored Constraints 
EMP network applications can monitor  the following inequality 
constraints: 
• Voltage :  Upper and lower limits on the voltage magnitude 
• Branch : Upper limits on the flow across lines and transformers 
• Interface : Upper and lower limits on the total net MW and/or MVAr 
flow across specified  sets of branches 
• Node pair : Upper limits on the difference in the voltage angle 
between the 2 specified nodes 
• Reserve Group : Min MW reserve  
In OPF, you activate/deactivate the monitoring of constraints individually, 
or by group, or by constraint type. 
1.2.3.2.2 Enforced Constraints 
When solving with OPF, you may wish that OPF enforces only a subset of 
the monitored constraints. 
Two views of the Optimization Constraint Definition  display --- similar to 
those used to specify the monitored elements --- allow you to specify the 
constraints to be enforced by OPF.  
Your task : Find these 2 views (Equipment and Group). Do not modify 
any data.  
The enforcement definition is the same as the logic used to control the 
monitored elements. Thus, in the Group view of the display,  you can 
enforce constraints by enforcement group, and in each enforcement group 
by constraint type, but you can also disable individual constraint from 
being enforced  ( Equipment   view ).  
In addition to this facility, the OPF options also allow  you to globally 
activate or deactivate the constraint enforcement by type.

Lab 1: OPF Problem Summary 
 
Objective 
Upon completion of these labs, you will be able to define and activate: 
• Controls 
• Control Groups 
This  lab contains a short summary on how to define the elements of the 
OPF problem. It introduces the multi-purpose mapping facility which is 
used in the problem definition. It also drives you to the main displays used 
to define the OPF problem elements. 
This lab is followed by a second lab to familiarize the student with how to 
create or modify the OPF problem definition. 
For these labs, you will use a specific savecase of the OPF application 
titled TRAIN_OPF_PROBLEM_DEFINITION. 
 
Task: Retrieve the OPF savecase titled 
TRAIN_OPF_PROBLEM_DEFINITION 
1.1 OPF Problem Definition Logic 
Defining the OPF problem means defining: 
• an objective function 
• controls that can be adjusted to reach the objective 
• constraints to be observed by the solution 
OPF provides a lot of flexibility in defining these elements of the OPF 
problem.  Flexibility involves some complexity. The following is  a 
summary of the logic and  displays provided in EMP’s OPF to define these 
3 elements and their links. Two main displays are used :  
• Optimization Constraint Definition   
• Define Controls  
These two displays each have several views which allow you to perform 
specific tasks related to the optimization problem definition.

1.1.1 Controls 
1.1.1.1 Control Availability 
You define available controls by selecting them from the Insert Controls    
analyst display (available from the Analyst menu). This display shows, by 
station, a list of all devices in the network model (NETMOM database) that 
are potential OPF controls. You make a control available to OPF by 
clicking on the [+/-]  button on the left of each control, which causes a 
control record to be inserted into the OPF control database (CTLMOM) for 
that device. (If you select the same device multiple times, the logic is 
smart enough to avoid duplicate controls.) 
You see the result of that selection in three views of the Define Controls 
display (which show data in the CTLMOM database): 
• Controls are listed by station in the View Controls tab   
• Controls are also listed by stati on in the Assign Controls tab, but 
with their group and cost curve assignments 
• Controls assigned to one or more  control groups are listed under 
their assigned group(s) on the Assign Groups tab 
1.1.1.2 Control assignment to Control Group(s) 
Controls can be assigned to Control Groups.  Control Groups belong 
hierarchically to Control Group Types. See the summary figure in section 
1.2. 
You define Control Group Types and Control Groups by inserting them 
[+/-] in the Define Groups view of the Define Controls display. 
You assign controls to control groups using the multi-purpose mapping 
facility  (introduced later). 
Note: Any control can be assigned to multiple control groups. 
1.1.2 Cost Curves 
1.1.2.1 Defining Cost Curves in Cost Curve Groups 
Cost curves are defined independently so as to allow several controls to 
use the  same  cost curve, if needed. However, only control variables can 
be assigned to have a cost curve, not the state variables. 
Cost curves belong hierarchically to cost curve groups.  See again the 
summary  figure in section 1.2. 
You create cost curve groups by inserting them [+/-] in the Cost view of 
the  Define Controls display.

You create cost curves by inserting them [+/-] under the desired cost 
curve group. 
You create incremental cost curve points (x, slope(x)) by inserting them 
[+/-] under the  desired cost curve in the same Cost view of the of the 
Define Controls  display. 
It should be mentioned that the use of cost curves is being de-emphasized 
in the latest version of OPF. The selection of minimum control changes to 
correct violations, previously handled using cost curves, is now done using 
the latest Control Selection logic. If is very easy to use cost curves to 
define problems that are difficult or impossible to solve, so cost curves 
should be used only when necessary to accurately model the problem 
definition.  
1.1.2.2 Assigning Cost Curves to Controls 
You associate cost curves and controls by using the multi-purpose 
mapping facility. 
Note 1 : Several cost curves  can be assigned to a control. 
Note 2 : A multiplier (SCALE) can be specified for each curve when 
assigning it to a control 
Note 3 : If a control has more than one cost curve assigned to it, the cost 
of moving that control will be defined by the composite sum of all assigned 
cost curves.  
1.1.3 Objective Functions 
You create objective functions by inserting them [+/-] in the Objective  
view of the  Define Controls  display.   
You define a particular objective function by assigning to it a curve group 
using the multi-purpose mapping facility. 
Note 1: Several cost curve groups can be assigned to an objective 
function. 
Note 2: The  resulting objective function will be the sum of all the costs 
derived from all the cost curves contained in the curve group(s).

1.3 OPF: Mapping Problem Definition Elements 
Mapping associates one of the elements of the problem definition (control, 
cost curve, objective) to one of the others. 
There are 3 possible bi-directional associations between mapping 
partners: 
• Objective Function   Å Æ  Cost Curve Group

partner(s) of that mapping operation. Direct navigation to the display(s)

OPF optimization problem definition.

and how to link these elements in the problem definition.
